# 状态机类功能的测法

> **适用语境**:被测功能有状态流转(单据状态机、退款单生命周期等)——中间态预置、逐态推进、终态守卫、资损红线断言
> **实证状态**:单项目(充电桩+mock 系统)实证——2026-10-15 券包退款实证:7 态全链 13/13 绿,资损红线=复用单号逐字一致;**非通用已验证**

- **状态机类功能的测法**(2026-10-15 券包退款实证):
  1. 先读码画出全状态图(每条迁移的守卫 WHERE)
  2. 中间态**交用户 SQL 预置**(如置失败态模拟"微信受理失败",AI 不直连 DB)
  3. 专用回写/推进接口逐态打(如模拟回调),每步发完立刻只读回查落库值
  4. 终态后再打一遍入口=守卫必拦
  5. 资损红线类断言盯"复用不变量"(如重试前后退款单号逐字一致)
  6. 写接口的请求预算按状态机节点数估,不按用例数
